## 一、Gate 1 解读合同（v0.5 核心变更）

一次 LLM 调用返回 JSON：

| 字段 | 规则 |
|---|---|
| `poem` | 四句五言或七言，押韵；不写成语、不写卦名、不回答会不会 |
| `interpretation` | 白话解签 80–150 字；默认折叠，点「请解签」展开 |

这替换了 v0.4 的三段散文（150–300 字），也没有把四层断卦放进产品输出。

## 四、规格内部还冲突的四处

| 位置 | 冲突 |
|---|---|
| §4 注 vs §9 | §4 仍写逆位要在 prompt 里再加一句。§9 写逆位规则已在 system prompt 里，不另加补丁。 |
| §5 示例 JSON | 示例停在 v0.4：没有 `voiceVector`、`arc`、`arcDesc`，标题仍写「待补字段」。文件里这些字段都在。 |
| §3.5 语气表 | 表中有「共情高」。16 个声音里没有共情。§9 已改成注入一个最高声音的独白，这张表没有改。 |
| §3.4 上限 0–100 | 每次抽卡加 3–6 点，MVP 不衰减，也没有封顶。约两周后，常被喂到的声音会超过 100。 |

## 五、没跟着改的文档

- 方法论第四节仍要求直接回答是或否，并给出时间窗口。
- 官方释义核对把四层解码称为产品要交付的厚 G。
- 规格 §16 的薄 G / 厚 G 指多牌阵的两轮 LLM，Round 1 仍写成「成语意象 + 位置语义」，没有改成签诗。
- 解卦卡 HTML（33 号比翼连枝）仍把方向断成「是」。
- `cards.json` 的 `version` 字段仍是 `0.1-draft`。
- `en` 仍是手册英文卡名的缩短或整句（如 36 号 `The crane rides the dragon turtle`）。版权条款只要求 `meaning` 改写。

## 六、样例擦边 · 36 号独占鳌头 · 正位 · 问财务

> 蛰久鱼龙未易猜，长风一送昼潮回。琼林树上花千朵，第一枝开为汝来。

白话解签写明不应读作「钱会自己来」。诗句「第一枝开为汝来」已经把结果指向提问的人。验收条「不直接回答会不会」需要一句可执行的判据，否则这四句算过还是算不过，抽查时没有标准。
